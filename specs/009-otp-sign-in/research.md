# Research: OTP sign-up and sign-in

Decisions taken while planning, with the alternatives. Owner-level decisions stay in the
charter (D3-1 to D3-13) and the spec's open questions.

| #   | Decision                                                                                                      | Alternatives rejected                       | Why                                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Challenges in PostgreSQL, counters in Redis                                                                   | All in Redis; all in PostgreSQL             | Challenges need transactions with account creation and audit (spec 003); counters need expiry and speed, and Redis already holds access tokens                        |
| R2  | Code hash is HMAC with a key derived by HKDF from the blind-index root                                        | bcrypt or scrypt of the code; plain SHA-256 | A 6-digit code has 20 bits: a slow hash does not protect it, a secret key does. Reuses an existing secret, no new parameter                                           |
| R3  | Challenge found by `challengeId` from the client, checked against the number's live challenge                 | Client sends the number again on verify     | Keeps the number out of a second request and out of browser history                                                                                                   |
| R4  | One error (410 `code_expired`) for expired, used, replaced and exhausted challenges                           | Distinct errors                             | Fewer signals to an attacker; the user's next step is the same                                                                                                        |
| R5  | Enumeration resistance by doing the same work for known and unknown numbers (blind index, challenge row, SMS) | Sending SMS only to known numbers           | Sign-up and sign-in are one flow, so every valid number gets a code anyway; same work gives same timing                                                               |
| R6  | Re-verification grant in Redis, bound to session and purpose                                                  | A claim inside the access token             | Access tokens are opaque Redis entries today (`AccessTokenStore`); a separate single-use key is simpler to spend                                                      |
| R7  | First-visit language choice by the proxy redirect when no `heach_locale` cookie                               | Accept-Language only (today)                | AC-02 asks for a choice on first launch; Accept-Language still picks the order of nothing, Odia stays first                                                           |
| R8  | Return path checked by an allow-list function shared by the proxy and pages                                   | `URL` parsing alone                         | `new URL('//evil', base)` resolves to another host; explicit rules are testable                                                                                       |
| R9  | WebOTP (`navigator.credentials.get({ otp })`) when present, `autocomplete="one-time-code"` always             | A third-party SMS retriever                 | Browser API, no dependency; SMS template ends with `@{host} #{code}` only where the host is known (dev uses an IP, so WebOTP works only from the pilot domain, FU-20) |
| R10 | Remove `user_test` and test sign-in here, not in 3.0                                                          | Keep them until a later slice               | Sessions need a user table; once OTP works E2E, a sign-in without a code is only risk (D3-9)                                                                          |
